# Data Card

## Overview

BalanceLab AI (M0) uses **synthetic data only**. No real, production, or
confidential financial data is present in this repository or produced by the
service while the `synthetic_data_only` policy is in force.

## Datasets

### Synthetic balance-sheet portfolios (generated at runtime)

- **Producer:** `balancelab.synthetic.generator` (version `synthetic-generator@1`).
- **How it is made:** a seeded pseudo-random generator (`random.Random(seed)`)
  draws account balances within fixed ranges; a single equity account is set to
  `total_assets − total_liabilities` so the balance-sheet identity holds by
  construction.
- **Reproducibility:** identical `seed` + parameters → identical portfolio. The
  seed and generator version are recorded in each portfolio's `Provenance`.
- **Labeling:** every generated portfolio carries `provenance.origin =
  synthetic`. This label is checked at the `ensure_synthetic` boundary.
- **Fields:** account name, category (`asset` / `liability` / `equity`),
  currency (`USD` / `EUR` / `GBP`), balance (`Decimal`, 2 dp).
- **Scale:** small by design (1–5 asset accounts, 1–5 liability accounts, 1
  equity account) — sized for deterministic demos and tests.

### Evaluation cases

- **File:** `evals/cases/golden_reconciliation.json` (version `1`).
- **Origin:** synthetic; derived deterministically from seeds. Golden totals are
  pinned; adversarial cases are constructed by corrupting a generated portfolio.

## What the data is / isn't

- **Is:** obviously-synthetic, illustrative balance sheets for demonstrating and
  testing deterministic computation and lineage.
- **Isn't:** representative of any real institution, benchmark-quality, or
  suitable for financial decisions. Account names (e.g. "Synthetic Demo Bank")
  are intentionally generic and fictitious.

## Privacy & licensing

- No personal data, no confidential employer data, no scraped third-party data.
- Generated data is original output of this project's code and carries the
  repository's [Apache-2.0](LICENSE) terms.
- `license_notes` on synthetic provenance states: *"Synthetic data generated by
  BalanceLab; no real entity."*

## Retention

As of M1, portfolios and snapshots are persisted when a database is configured
(otherwise they live only for the process lifetime, in memory). Stored data is
synthetic only. A formal retention/deletion policy (TTL, purge tooling) is not
yet implemented; because all stored data is synthetic and reproducible from a
seed, dropping and recreating the database is the current reset path. This will
be formalized alongside authentication and audit (M3).

## Provenance for future non-synthetic sources

The `Provenance` model already reserves fields required by the spec for
source-derived data (`source_uri`, `retrieved_at`, `content_checksum`,
`license_notes`). These are unused in M0 but will be populated — and required —
when public/licensed sources are introduced.
